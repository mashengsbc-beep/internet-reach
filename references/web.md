# Web

Use this reference for public webpages, articles, documentation pages, blog posts, and RSS-like reading tasks.

## Retrieval order

1. If the user already gave a URL, fetch it directly.
2. If no URL is given, search the web for likely primary sources.
3. Prefer official docs, source repos, and primary posts over summary blogs.

## Reading rules

- Preserve structure when possible: headings, lists, code blocks, tables.
- Separate source claims from your conclusions.
- If a page is obviously marketing-heavy, look for implementation pages, docs, changelog, source, or issues.

## Practicality filter

For tools/projects described on the web, evaluate:
- setup cost
- hidden dependencies
- auth requirements
- rate limits / lock-in
- whether the "simple" flow only works in demos

## Good outcomes

Aim to extract:
- the smallest useful mental model
- what the user can actually do next
- what should become reusable guidance in this workspace
