# GitHub 项目分析模板

适用于：

- 看一个仓库值不值得用
- 看一个项目适不适合接入当前环境
- 看一个热门工具到底是不是营销大于实际

## 输出模板

### 1. 一句话结论
先给总体判断：值得用 / 值得学 / 值得部分吸收 / 不建议依赖。

### 2. 它解决什么问题
- 目标痛点
- 为什么这个痛点是真问题

### 3. 它真正可用的部分
- 零配置可用
- 配置后可用
- 在当前环境里最可能成功的路径

### 4. 它的代价和风险
- 依赖项
- 登录 / Cookie / 代理 / MCP / 第三方 CLI
- 维护成本
- 风控和稳定性问题

### 5. 适用场景
- 个人使用
- 研究 / 调研
- 原型期
- 生产环境

### 6. 我会怎么处理它
从下面四类里选：
- 直接采用
- 部分吸收
- 学方法不学实现
- 暂不采用

### 7. 如果要继续推进，下一步是什么
例如：
- 做一个更小的本地 skill
- 先在一个真实任务上试跑
- 只引入其中一个核心能力
