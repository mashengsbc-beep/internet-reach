# Evidence Order

Use this reference to decide what to trust first when researching internet-facing tools or projects.

## Trust order

Prefer evidence in roughly this order:

1. **Source code / config / tests**
2. **Official docs / README / changelog**
3. **Issues / PRs / commit history / release notes**
4. **Primary demos / videos / screenshots**
5. **Community posts / discussions / third-party summaries**
6. **Marketing copy**

## Practical use

### Trust code more than README
If README says "works everywhere" but code shows many optional dependencies, say so.

### Trust issues more than polished examples
If examples look smooth but issues show repeated setup failure, mention the gap.

### Trust recency and maintenance patterns
A flashy repo with stale commits or unresolved breakages is weaker than a smaller but maintained one.

### Trust direct inspection over paraphrased blog claims
When possible, inspect the repo, docs, and issues yourself.

## Reporting rule

When evidence conflicts:
- say what the project claims
- say what the code/issues suggest
- explain your confidence level
