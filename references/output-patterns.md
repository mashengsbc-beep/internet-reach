# Output Patterns

Use these response shapes to keep internet research outputs practical.

## Pattern A — Quick practicality verdict

Use for: "值不值得用？", "实用性怎么样？"

Structure:
- One-line verdict
- Main strengths
- Main weaknesses
- Best-fit scenario
- Recommendation

## Pattern B — Analyze and learn

Use for: "分析一下，然后你也学一下"

Structure:
- What it is
- What is practically useful
- What is fragile / conditional
- What I would absorb into my own workflow
- Final recommendation

## Pattern C — Tool adoption decision

Use for: deciding whether to install/adopt a project in this workspace

Structure:
- Directly usable now
- Requires extra setup
- Unsafe / brittle / high-maintenance parts
- Minimal adoption plan
- Whether full installation is justified

## Pattern D — Repo deep read

Use for: "看看这个 GitHub 项目"

Structure:
- Repo snapshot (activity, stars, maintenance signal)
- Claimed capabilities
- Actual implementation shape
- Operational dependencies
- Realistic use cases
- Adoption decision
