# Research Playbooks

Use this reference when you need a repeatable internet-research workflow instead of one-off browsing.

## Playbook 1 — Inspect a GitHub project

Use when the user says:
- "看看这个 GitHub 项目"
- "分析一下这个 repo"
- "去 GitHub 学学这个怎么做"

Steps:
1. Get repo metadata and recency.
2. Read README for claimed value.
3. Inspect root tree and key implementation files.
4. Check recent commits, open issues, open PRs.
5. Judge practicality using `evaluation.md`.
6. Extract reusable methods, not just opinions.

Good outcome:
- concise verdict
- what is real vs promotional
- what to adopt, adapt, or avoid

## Playbook 2 — Evaluate a tool from a URL

Use when the user sends a docs page, homepage, article, or launch post.

Steps:
1. Read the URL directly.
2. Identify whether it is docs, marketing, blog, or source.
3. Look for linked repo, docs, install steps, or API reference.
4. Verify claims using source material when available.
5. Report setup burden, hidden dependencies, and fit.

## Playbook 3 — Cross-check hype vs reality

Use when a project sounds very powerful or broad.

Steps:
1. List the major claims.
2. Find code/docs that support each claim.
3. Find issues/PRs/discussions that weaken or qualify those claims.
4. State what appears robust, conditional, or speculative.

## Playbook 4 — Learn and internalize

Use when the user says:
- "你也学一下"
- "变成你自己的 skill"
- "以后照这个做"

Steps:
1. Identify the durable method, not just the specific toolchain.
2. Separate what belongs in long-term memory vs only this skill.
3. Prefer rules that improve future routing and judgment.
4. Adapt the idea to current OpenClaw-native tools.
5. Keep the resulting skill smaller and more reliable than the source project.
