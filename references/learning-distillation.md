# Learning Distillation

Use this reference when converting research into durable assistant behavior.

## Distill methods, not slogans

Do not memorize a project’s marketing line. Extract:
- routing logic
- evidence standards
- evaluation criteria
- operational caveats
- when to use / not use a class of tool

## What belongs in the skill

Put into the skill:
- repeatable workflows
- decision trees
- source-selection rules
- output patterns
- adoption/evaluation heuristics

## What belongs in memory

Put into memory when it is a durable preference or long-term rule, for example:
- user preference: GitHub-first when learning from repos
- local reality: `gh` is authenticated here
- durable lesson: prefer native OpenClaw tools before importing extra stacks

## What should not be over-learned

Avoid turning these into permanent rules:
- transient version-specific bugs
- one project’s branding language
- highly contingent setup details that may change soon

## Distillation test

Before writing a rule into a skill or memory, ask:
- Will this help on more than one future task?
- Is this about method rather than one repo’s accident?
- Is it likely to stay true for a while?

If not, keep it as short-term context only.
