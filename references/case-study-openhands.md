# 案例：OpenHands/OpenHands

## 项目类型
平台型项目。

## 快速判断
这是一个**产品化叙事强、能力面广、真实实现也很重**的平台项目。

## 为什么它有吸引力
- README 展示层很强
- 产品形态分层清晰：SDK / CLI / Local GUI / Cloud / Enterprise
- 仓库活跃，提交和 PR 频繁
- 依赖和功能面都非常大

## 需要警惕的地方
- 平台能力越多，落地复杂度越高
- README 很容易让人先被产品叙事带着走
- 实际部署、依赖、模型兼容、前后端问题仍然很多

## 评分示例
- Practical utility: 5
- Local fit: 3
- Operational burden: 2
- Reliability: 3
- Adoption worthiness: 3
- Total: 16/25

## adopt / adapt / avoid
- **Adopt directly**：不建议在当前环境里整套直接重依赖
- **Adapt**：适合学习它的产品分层、能力拆分、平台组织方式
- **Avoid blindly**：不要被大而全叙事诱导成低估实施成本

## 学到的规则
面对产品化很强的平台项目，要强制加入两道判断：
1. README 叙事和真实部署成本是否一致
2. 这东西适合“接入当前环境”，还是更适合“学习其组织方式”
